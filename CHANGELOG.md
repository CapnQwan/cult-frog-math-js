## [Unreleased]

### Added

- Vector types `Vec2`, `Vec3` and `Vec4`, with `ReadonlyVec2`, `ReadonlyVec3` and `ReadonlyVec4`, and the `Vec2`, `Vec3` and `Vec4` namespaces with `create`, `clone`, `set`, `copy`, `isEqual` and `isEqualEpsilon`, plus `isEqualXY`, `isEqualXYZ` and `isEqualXYZW` respectively to compare against loose components.
- Vector arithmetic on `Vec2`, `Vec3` and `Vec4`: `add`, `sub`, `mul`, `div` and `scale`. `mul` and `div` work per component, and `div` follows normal float rules, so a zero divisor gives `Infinity` or `NaN` rather than a guarded value.
- Vector measurement on `Vec2`, `Vec3` and `Vec4`: `magnitudeSq`, `magnitude`, `distanceSq`, `distance` and `normalize`. `normalize` turns a zero vector into a zero vector rather than `NaN`.
- Vector products: `dot` on `Vec2`, `Vec3` and `Vec4`, and `cross` on `Vec3`. `cross` follows the right-hand rule.
- Vector helpers on `Vec2`, `Vec3` and `Vec4`: `scaleAndAdd`, `negate`, `lerp`, `reflect` and `angle`. `scaleAndAdd` writes `a + b * scalar`, `lerp` is unclamped, like the scalar `lerp`, `reflect` expects a normal with a length of `1`, and `angle` returns radians and gives `0` for a zero vector.
- Per-component vector helpers on `Vec2`, `Vec3` and `Vec4`: `abs`, `min`, `max`, `floor`, `ceil` and `round`. `min` and `max` compare two vectors and can mix components from both, `floor` rounds toward negative infinity, and `round` rounds halves toward positive infinity, like the scalar `round`, but takes no `decimals`.
- Packed reads on `Vec2`, `Vec3` and `Vec4`: `fromPacked` copies one row of a tightly packed array into `out` without making a view. The index is a row, not an element offset, and bounds aren't checked, so a component read from outside the array is written as `NaN`. Each namespace also gets a `SIZE` constant.
- Vector constants: `ZERO` and `ONE` on `Vec2`, `Vec3` and `Vec4`, `UP`, `DOWN`, `LEFT` and `RIGHT` on `Vec2` and `Vec3`, plus `FORWARD` and `BACK` on `Vec3`. The 3D axes are y-up and right-handed, so `FORWARD` is negative z and `BACK` is positive z.
- Matrix types `Mat2`, `Mat3` and `Mat4`, with their `Readonly*` variants, and the `Mat2`, `Mat3` and `Mat4` namespaces with `create`, `clone`, `set`, `copy`, `identity`, `isEqual`, `isEqualEpsilon`, `multiply`, `transpose`, `determinant` and `invert`, plus `IDENTITY` and `SIZE` constants. Matrices are stored column major; `create` and `set` take their arguments in row-major order. `create()` gives the identity matrix: omitted elements default to `1` on the diagonal and `0` elsewhere, so a partial argument list keeps the rest of the identity. `multiply(out, a, b)` writes the product `a * b`, which applies `b` first and then `a`, like `Quat.multiply`, and `out` may be either input. `transpose` copies every element exactly and can work in place; it is the inverse only for a pure rotation, not once the matrix scales, shears or translates. `determinant` returns a number rather than writing to `out`: its magnitude is the area or volume scale, it is negative when the matrix mirrors, and zero means the matrix has no inverse. It is computed in float64 and not rounded to float32, so test it against a tolerance rather than `=== 0`. `invert` returns `null` for a matrix whose determinant is exactly zero or `NaN`, so for any `NaN` element, and leaves `out` untouched, so its result must be checked before use. There is no tolerance, since one would reject small but valid matrices, so a nearly singular matrix inverts to very large elements. Infinite elements are not caught: an infinite determinant gives zeros and `NaN` rather than an inverse.
- 2D affine transform type `Mat3x2` and `ReadonlyMat3x2`, and the `Mat3x2` namespace with `create`, `clone`, `set`, `copy`, `identity`, `isEqual`, `isEqualEpsilon`, `multiply`, `determinant` and `invert`, plus `IDENTITY` and `SIZE` constants. A `Mat3x2` is 6 floats, 3 columns of 2 rows in column-major order, which is the layout of WGSL's `mat3x2<f32>` and of `uniformMatrix3x2fv`; a std140 uniform block pads it to 48 bytes, and arrays of it in a WGSL uniform buffer need padding to a 16-byte stride. The bottom row of the full 3x3 matrix is always `0 0 1` and isn't stored, so every `Mat3x2` is affine: it can translate, rotate, scale and shear, but not project. A `Mat3` won't type-check as one. There is no `transpose`, since the transpose of a 3x2 matrix isn't one. `multiply`, `determinant` and `invert` behave as on the other matrices, except that the translation never affects the determinant, so `invert` returns `null` only when the 2x2 linear part is singular or holds a `NaN`; a `NaN` translation inverts to a `NaN` translation.
- Matrix-vector transforms: `Vec2.transformMat2`, `Vec2.transformMat3x2`, `Vec2.transformDirectionMat3x2`, `Vec3.transformMat3`, `Vec3.transformMat4`, `Vec3.transformDirectionMat4` and `Vec4.transformMat4`. Each writes the product `m * v`, with `v` as a column vector like `multiply`, so transforming by `multiply(tmp, a, b)` is transforming by `b` and then by `a`. When the vector is one component short of the matrix, the function name says what it is: `Vec2.transformMat3x2` and `Vec3.transformMat4` treat it as a point, so the translation applies. `Vec3.transformMat4` also divides by the resulting `w`, which makes it correct under projection too and changes nothing for an affine matrix; a point that lands at `w = 0` gives `Infinity` or `NaN` rather than a guarded value. `Vec2.transformMat3x2` divides nothing, since a `Mat3x2` is always affine. `transformDirectionMat3x2` and `transformDirectionMat4` treat it as a direction, reading only the 2x2 linear part or the upper-left 3x3, so the translation is ignored; `transformDirectionMat4` is meaningful only for an affine matrix. None of them is correct for surface normals under non-uniform scale, which need the inverse-transpose. `Vec4.transformMat4` uses the `w` it is given and divides nothing, so a projected point stays in clip space.
- Matrix builders: `Mat4.fromTranslation`, `Mat4.fromScale`, `Mat4.fromQuat`, `Mat4.fromAxisAngle` and `Mat4.fromTRS`; `Mat3x2.fromTranslation`, `Mat3x2.fromRotation`, `Mat3x2.fromScale` and `Mat3x2.fromTRS`; `Mat3.fromQuat`; and `Mat2.fromRotation` and `Mat2.fromScale`. Each overwrites every element of `out` with a new transform rather than applying it to the matrix already there, so combine transforms with `multiply`. Translation and scale are exact, with the translation in the last column; rotations are only close to exact, so compare them with `isEqualEpsilon`. `fromTRS` builds `T * R * S` in one pass: scale first, along the object's own axes, then rotate, then translate. `Mat4.fromQuat`, `Mat3.fromQuat` and `Mat4.fromTRS` expect a unit quaternion and match `Vec3.transformQuat`; `Mat4.fromAxisAngle` follows the right-hand rule like `Quat.fromAxisAngle` and expects a unit axis, which it does not normalise. The `Mat3x2` builders are 2D: they take `Vec2`s and an angle, with the translation in the last column as `Vec2.transformMat3x2` expects. `Mat3.fromQuat` is the 3D rotation-only matrix that `Vec3.transformMat3` uses; a `Mat3` never holds a translation. 2D rotations turn counter-clockwise for a positive angle in the package's y-up convention, which looks clockwise in y-down screen space.
- Quaternion type `Quat` and `ReadonlyQuat`, and the `Quat` namespace with `create`, `clone`, `set`, `copy`, `identity`, `isEqual`, `isEqualEpsilon`, `isEqualXYZW`, `isEqualRotation`, `multiply`, `dot`, `angle`, `magnitudeSq`, `magnitude`, `normalize`, `conjugate`, `invert`, `rotateX`, `rotateY`, `rotateZ`, `slerp`, `nlerp`, `toAxisAngle`, `fromAxisAngle`, `fromEuler` and `fromUnitVectors`, plus `IDENTITY` and `SIZE` constants. Quaternions are stored as `[x, y, z, w]`, and `create()` gives the identity rotation, since `w` defaults to `1`. `multiply(out, a, b)` composes rotations, applying `b` first and then `a`, like column-vector matrices, and does not renormalise. `normalize` turns the zero quaternion into the identity, unlike the vector `normalize`, which keeps a zero vector at zero. `conjugate` is the inverse only for unit quaternions; `invert` divides it by the squared length so it also inverts non-unit ones, and like `normalize` it turns the zero quaternion into the identity. `rotateX`, `rotateY` and `rotateZ` turn a quaternion about its own axis, the same as multiplying it on the right by `fromAxisAngle` of that axis, and do not renormalise. `slerp` and `nlerp` expect unit inputs, always take the shorter path (so `t = 1` can give `-b`), and do not clamp `t`. `slerp` turns at a constant angular speed and falls back to `nlerp` for rotations within about 3.6° of each other. `nlerp` is cheaper but slower near the ends, and it falls short when extrapolating. `angle(a, b)` gives the angle between two rotations from `0` to `π`, treating `q` and `-q` as the same and staying accurate for near-identical rotations. `toAxisAngle(outAxis, q)` writes the unit axis and returns the angle, from `0` to `π`, rather than returning its `out` parameter; it reads a turn of more than half a revolution as the shorter turn about the reversed axis, and a rotation of zero gives `Vec3.RIGHT` and `0`. `fromAxisAngle` follows the right-hand rule and expects a unit axis, which it does not normalise. `fromUnitVectors(out, from, to)` gives the shortest rotation between two unit directions; for directions within about 0.08° of opposite it gives a half turn about an axis chosen to keep a horizontal `from` upright. `fromEuler(out, x, y, z)` takes pitch, yaw and roll in radians and uses the Y-X-Z order, `qy * qx * qz`: roll is applied first and yaw last. `Vec3.transformQuat` rotates a vector by a unit quaternion; a non-unit quaternion does not give a scaled rotation. `isEqual`, `isEqualEpsilon` and `isEqualXYZW` compare components, so `q` and `-q` are not equal even though they represent the same rotation. `isEqualRotation` compares rotations instead, with a tolerance in radians, so `q` and `-q` are equal; the zero quaternion is equal only to another zero.
- Linear colour type `Color` and `ReadonlyColor`, and the `Color` namespace with `create`, `clone`, `set`, `copy`, `isEqual`, `isEqualEpsilon`, `isEqualRGB`, `isEqualRGBA` and `lerp`, plus `SIZE` and the constants `WHITE`, `BLACK`, `RED`, `GREEN`, `BLUE`, `YELLOW`, `CYAN`, `MAGENTA` and `TRANSPARENT`. Colours are stored as `[r, g, b, a]` with linear channels from `0` to `1`. Nothing clamps, so values above `1` are valid HDR channels, and colours are not premultiplied. `create` defaults alpha to `1`, while `set` requires it. `isEqualRGB` ignores alpha, and `lerp` is unclamped.
- Packed colour type `Color32` and the `Color32` namespace with `create`, `red`, `green`, `blue`, `alpha` and `lerp`, plus the same named constants as `Color`. A `Color32` is an sRGB-encoded 8-bit RGBA colour packed into one unsigned number as `0xRRGGBBAA`, so it compares directly against a CSS-style hex literal. `create` rounds each channel to the nearest integer and then wraps it to 8 bits, with no clamping, and defaults alpha to `255`. `lerp` blends the encoded values, then clamps each channel to `0`–`255`.
- Colour conversions: `Color.fromColor32` decodes a `Color32` into `out` with the sRGB transfer function, and `Color32.fromColor` encodes a `Color` back. Alpha is only scaled, never encoded. `fromColor` saturates every channel to `0`–`1` first, so HDR values clip to `255` rather than wrapping and negative channels become `0`. `NaN` channels are packed as `0`. Every `Color32` survives a round trip through `Color`, and the named constants match exactly in both namespaces.
- Scalar helpers: `clamp`, `saturate`, `round`, `wrap`, `snapToZero` and `isEqualEpsilon`.
- Interpolation helpers: `lerp`, `invLerp`, `smoothstep` and `smootherstep`. `lerp` is unclamped, while the others clamp their result to `[0, 1]`.
- The `Easing` namespace, with `easeIn`, `easeOut` and `easeInOut` on `Easing.Quad`, `Easing.Cubic`, `Easing.Quart` and `Easing.Quint`, plus `smoothstep` and `smootherstep` on `Easing.Smooth`. Every curve takes a single `t` and does not clamp it. Available from the `@cult-frog/math/easing` subpath and the package root.
- Constants: `EPSILON`, `EPSILON_SQUARED`, `PI` and `TWO_PI`.
- A subpath export per type (`@cult-frog/math/vec3`, `@cult-frog/math/mat4`, `@cult-frog/math/quat`, `@cult-frog/math/color`, `@cult-frog/math/color32`, ...), each exporting its namespace and types. The package root exports all of them.
- All values except `Color32` are branded `Float32Array`s and can be views over either an `ArrayBuffer` or a `SharedArrayBuffer`. `Color32` is a branded number.
